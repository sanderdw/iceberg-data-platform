Frequently asked questions¶

Short answers, each with a link to the page that has the details.

About the platform¶

Can I run it in production?¶

No. This is an educational local development platform. It has not had an independent security audit, only the latest release receives fixes, each portal runs as one replica, and with Compose the user portal mounts the Docker socket. The Kubernetes chart replaces that socket with narrow namespace rights and HTTPS, but the rest still applies. Reuse the architecture and the choices behind it, not the installation itself. See the security model and deploying beyond localhost.

Install and run¶

What do I need?¶

Docker with Compose v2 (Docker Desktop on macOS and Windows) and at least 4 GiB of Docker memory, on AMD64 or ARM64. You don't need Python, Node.js or a source checkout. See installation. On a Kubernetes cluster you need Helm, an ingress controller and cert-manager instead; see Install on Kubernetes.

Where is the first password?¶

The installer prints it at the end. It is also PLATFORM_ADMIN_PASSWORD in .env in the installation directory. On Kubernetes, read it from the Secret iceberg-platform; see addresses and sign-in. Sign in to the administration portal as platform-admin and choose a new password. See first steps.

How should I get started?¶

Install only the core platform and follow the first steps. You can add extensions later.

How do I update?¶

Run the installer again. It keeps .env and the data volumes. Save your notebook work and read the release notes first. See update or restart. On Kubernetes, run helm upgrade; see update.

How do I start completely fresh?¶

Stop every Compose project with docker compose down --volumes, then remove the team notebook volumes (iceberg-workspaces-work-*), which down never removes. This deletes all data and can't be undone. See stop and preserve data. On Kubernetes, helm uninstall keeps the data; delete the namespaces to remove it (see uninstall).

Can people in my class use one installation from their own laptops?¶

Yes. A Kubernetes installation has public HTTPS addresses already, for a class of any size. With Compose it works with limits: the quick-share skill gives the portals public HTTPS addresses for the session through Cloudflare quick tunnels, but quick tunnels have serious limitations. For anything more than a short session, use a stable Cloudflare Tunnel, or let everyone run their own local installation.

Accounts and access¶

I'm a team Administrator. Why can't I open the administration portal?¶

The administration portal needs the Keycloak role iceberg-admin/platform-admin. Team roles never grant it, including the Administrator role. See the administration guide.

What can Read, Read & write and Administrator do?¶

A role applies to every database of that team. The roles are described under teams, databases and users.

A user forgot their password.¶

A platform administrator uses Reset password on the Users page, which issues a new temporary password. That works only for accounts the portal created. Reset a linked account in the Keycloak console (on Kubernetes through a port-forward; see addresses and sign-in). See the administration guide.

Notebooks and your own tools¶

A package I installed is gone.¶

Packages you install with marimo's package installer go to /tmp/packages and disappear when the notebook container stops. Add permanent dependencies to the notebook image. See notebooks.

Can two people edit the same notebook?¶

Teammates share the saved files, but it isn't a collaborative editor. Agree who edits a file. See notebooks.

My DuckDB session stopped working after an hour.¶

The token it started with lasts one hour. From your computer, run the iceberg_connect.py command again. In a notebook, reconnect the DuckDB attachment or call refresh_table_credentials. See connect from your computer and notebooks.

iceberg_connect.py only works on the platform's machine.¶

With Compose, Keycloak, Polaris and RustFS listen on 127.0.0.1. (A Kubernetes installation has public addresses; download the helper from its user portal.) Start the quick-share skill, then download the helper again from the user portal (Catalog › Connect from your computer), so it has the public addresses. See connect from your computer.

Why are dates and times in UTC?¶

Sessions run in UTC, so a date cast from a timestamp is the same on every computer. SET TimeZone = '…' changes it for one session. See connect from your computer.

Semantic models and AI agents¶

What is a semantic model, and when do I need one?¶

A semantic model says what the tables in a namespace mean: datasets, fields, relationships and agreed metrics. Polaris stores it next to the tables. Governed queries such as query_semantic_model and Conversational BI need one, so an agent answers from the agreed metrics instead of writing its own SQL. See semantic models.

Which AI agents work?¶

The docs cover Claude Code, Codex and GitHub Copilot in VS Code and the CLI. Any other MCP client works if it supports streamable HTTP and OAuth with the public client ID iceberg-mcp. See AI agents and connect an MCP client.

Does my data go to an LLM?¶

The core platform sends nothing to an LLM (or anything else). A coding agent you connect sees what its tools return. Conversational BI sends the conversation, the compiled SQL and at most 20 rows of each result (BI_LLM_ROWS) to the LLM provider you configure. To keep data on your own hardware, point OPENAI_BASE_URL at a local OpenAI-compatible server. See what goes to the LLM.

Extensions¶

How do I add an extension later?¶

Run the installer again and answer yes, or name the extensions in ICEBERG_EXTENSIONS. On Kubernetes, register it in the platform chart and install its chart; see add extensions. It keeps the extensions you already added, with their data. The installer doesn't add OpenMetadata; it has its own installer. See extensions.

Ingestion refuses my local database.¶

Sources on loopback, private or link-local addresses are refused. For a demo against a database on your own computer, set ING_ALLOW_PRIVATE_SOURCES=true in ingestion/.env and restart the extension. The run then reaches your computer as host.docker.internal. On Kubernetes, install the chart with runs.allowPrivateSources=true to reach sources in your own network. See isolation and limits.
