# Iceberg Data Platform 0.5.0

Release date: 2026-09-22

## Changes

- Prevent notebook thread exhaustion when several notebooks are open by bounding native numerical thread pools; concurrent flights generation is checked under runtime resource limits.

- Share selected tables and views with another team, external recipients, or both. Team members use their own accounts, and access follows membership, expiry and revocation.
- Received shares appear in Catalog and Notebooks as read-only databases. Recipient teams can open notebooks without owning a database; their saved files stay in their own team/environment workspace.

- MCP endpoints for workspace users and platform administrators, authenticated through Keycloak. Users explore their catalogs with their own permissions; team administrators can manage their databases. Platform administrators can manage platform resources.
- A separate **Databases** menu in the user portal, with creation, renaming, deletion and recovery of incomplete deletions. The team overview keeps its database summary and links to **Manage databases**.
- Authenticated workspace API documentation at `http://localhost:3002/docs`, with working Swagger requests and the same team permissions as the portal.
- Shared notebook display helpers and DuckDB flight-data examples for reading and writing Iceberg tables.

See the [changelog](../../CHANGELOG.md) for details.

## Upgrade from 0.4.1

No data migration is required. Preserve your existing configuration and PostgreSQL,
RustFS, pgAdmin and shared notebook volumes.

Update all three application images: portal, users and notebook. Restart the platform
so `keycloak-bootstrap` registers the new `iceberg-mcp` client. Existing installations
can set `MCP_CALLBACK_PORT` in `.env`; its default is `3010`. Users must sign in again
after the portals restart. Newly started notebook sessions use the updated notebook image.

Existing shares remain external; no share conversion is required. Sharing destinations
are fixed at creation: revoke and recreate a share to change them. Internal sharing
requires updated portal and user images so creation, membership changes and revocation
apply the same grants. Update the notebook image to receive the shared-data starter;
existing saved notebooks are preserved, and the new starter is added as
`shared_workspace.py`.

## Install this version

These commands become available after the release workflow publishes `v0.5.0`.

Linux / macOS:

```bash
curl -fsSL https://github.com/sanderdw/iceberg-data-platform/releases/download/v0.5.0/install.sh | sh
```

Windows PowerShell:

```powershell
irm https://github.com/sanderdw/iceberg-data-platform/releases/download/v0.5.0/install.ps1 | iex
```

The installers pin the installation bundle and all application images to `0.5.0`.
Docker with Compose is required. The release workflow builds images for Linux AMD64
and ARM64.

## Publication

Follow the [release workflow](../releasing.md). Merge the reviewed changes into
`main`, wait for hosted CI, then tag that commit `v0.5.0`. Pushing the tag triggers
image builds and publication of the source archive, installation bundle, installers
and checksums.
