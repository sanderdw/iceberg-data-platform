# Iceberg Data Platform 0.9.1

Release date: 2026-10-13

## Changes

- **List a data product in your data catalog.** Next to another team and external sharing, a data share can be **Listed in the data catalog**: names, schemas, descriptions and semantic models, never data or a credential. See [data shares](../data-shares.md#what-a-listing-publishes).
- **OpenMetadata extension 0.1.0** publishes listed shares to OpenMetadata 2.0 as tables, metrics, lineage and a data product, with semantic models as glossary terms and field labels as tags. You register it yourself; see [OpenMetadata](../openmetadata.md).
- Extension Bridge contract 0.1.1 adds the `listings` capability.
- Example notebooks 09 and 10 publish and read an AI-ready MV load forecast with Polars 2: lazy generation, contract checks in Polars SQL, Polars' Iceberg sink and scan, and a semantic model in Polaris.
- The flights example's semantic model describes every field and labels it with its ontology concept.
- A shorter changelog: the 0.9.0 entry now lists what changes for you, and 0.8.0 is marked as not released.
- The [presentation](https://sanderdw.github.io/iceberg-data-platform/presentation/) covers all four extensions, data catalog listings with OpenMetadata, and the current component versions.

See the [changelog](../changelog.md) for details.

## Install this version

Linux / macOS:

```bash
curl -fsSL https://github.com/sanderdw/iceberg-data-platform/releases/download/v0.9.1/install.sh | sh
```

Windows PowerShell:

```powershell
irm https://github.com/sanderdw/iceberg-data-platform/releases/download/v0.9.1/install.ps1 | iex
```

The installers pin the installation bundle and all application images to `0.9.1`, Conversational
BI to `0.1.1`, the dbt extension to `0.1.0` and Ingestion (dlt) to `0.1.0`. In a terminal the
installer asks which extensions to add; `ICEBERG_EXTENSIONS=conversationalbi,dbt,ingestion` adds
all three without questions. Docker with Compose is required. The release workflow builds images
for Linux AMD64 and ARM64.
