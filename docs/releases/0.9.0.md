# Iceberg Data Platform 0.9.0

Release date: 2026-10-12

## Changes

- **dbt pipelines**, the second extension: AI agents create dbt v2 projects for a team, write models and tests on a branch, build them in development and schedule them, through an API and MCP server. A team administrator enables it per environment and merges to `main`; acceptance and production build only `main`. Each run is an isolated container that writes as the team's service account with a short-lived token. See [installation](../install.md#add-dbt-pipelines).
- **Follow and edit pipelines in the dbt viewer**: status and tests of every model per environment and branch, live builds, lineage, row previews and schedules. Writers edit a model, save it to a branch and build that branch in development; team administrators merge it to `main`.
- **dbt from your terminal.** Download `iceberg_dbt.py` from the dbt viewer and type `build`, `test` or `show` as in the dbt docs; the commands run on the platform and stream the log back.
- **Ingestion (dlt)**, the third extension: load REST APIs, PostgreSQL and MySQL or MariaDB tables, and CSV, JSONL or Parquet files over HTTPS or S3 into your team's databases with declarative [dlt](https://dlthub.com/docs) pipelines, on demand or on a schedule. A page, an API and an MCP server offer the same actions. Team administrators enable it per environment, create pipelines and set their secrets, which are encrypted and write-only; writers start runs. Each run is an isolated container that writes as the team's service account. See [installation](../install.md#add-ingestion-dlt).
- **Load data with dlt in a notebook.** The new example 08 loads paged API data into `raw_dlt_demo` with your own identity and merges on a key, so a rerun adds no duplicates. `user_portal.notebook.connection` gains `dlt_destination()` for your own dlt pipelines.
- **`POLARIS_TOKEN_LIFETIME` sets how long service-account tokens and vended storage credentials last** (one hour by default). A dbt or Ingestion run ends 15 minutes before its token expires; raise the lifetime, for example to 7200, for longer runs.
- In the catalog, a table that a dbt build or an Ingestion run produces links to its pipeline under **Produced by**. The user portal links to the extensions as **Pipelines** and **Ingestion (dlt)**.
- Two more agent skills in the installation folder: `dbt-platform` builds, tests and schedules dbt pipelines and offers a semantic model for each finished mart; `ingestion` sets up a load from a template and runs it.
- Publishing a semantic model fills the descriptions it leaves out from the table comment and column docs, such as those a dbt build writes.
- Smaller images: the notebook image shrinks from 3.3 to 2.1 GB, the user portal's from 0.9 to 0.65 GB and the portal's from 0.6 to 0.44 GB.
- Updated dependencies, including Python 3.14.8, uv 0.13.0, FastAPI 0.143.0, Keycloak 26.8.0 and RustFS 1.0.1. Notebooks get Polars 2; see the [Polars 2 upgrade guide](https://docs.pola.rs/releases/upgrade/2/) for your own notebooks.

See the [changelog](../../CHANGELOG.md) for details.

## Install this version

Linux / macOS:

```bash
curl -fsSL https://github.com/sanderdw/iceberg-data-platform/releases/download/v0.9.0/install.sh | sh
```

Windows PowerShell:

```powershell
irm https://github.com/sanderdw/iceberg-data-platform/releases/download/v0.9.0/install.ps1 | iex
```

The installers pin the installation bundle and all application images to `0.9.0`, Conversational
BI to `0.1.1`, the dbt extension to `0.1.0` and Ingestion (dlt) to `0.1.0`. In a terminal the
installer asks which extensions to add; `ICEBERG_EXTENSIONS=conversationalbi,dbt,ingestion` adds
all three without questions. Docker with Compose is required. The release workflow builds images
for Linux AMD64 and ARM64.
