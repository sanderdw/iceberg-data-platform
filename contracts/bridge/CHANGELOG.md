# Bridge contract changelog

## 1.0.0 - unreleased

Released with core 1.0.0. The first stable contract (see [COMPATIBILITY.md](COMPATIBILITY.md)).

Added: the Settings page that every extension copies unchanged, [`v1/settings/`](v1/settings). Its first option,
Environments, is where an extension is enabled for each of the caller's teams, with Enable and Disable for team administrators. It calls only the
extension's own API, so the REST contract is unchanged.

Added: the account menu every extension copies unchanged, [`v1/account-menu/`](v1/account-menu), which both portals
use too: the person's name, opening their teams and roles, Getting started, the theme switch and Sign out, and the
Read-only pill's style. The Apps menu's selectors start at `.apps-anchor`, so a
page's own button styles no longer override them.
**Breaking:** extensions built for 0.1.x do not work with it. Declare `bridge-contract = ">=1.0,<2"`.

Breaking changes, so the Bridge follows the [API conventions](../../docs/develop/api-conventions.md):

- Times are RFC 3339 strings in UTC with milliseconds, such as `2026-11-24T09:15:02.123Z`:
  - `AutomationPrincipal.createdAt` was epoch milliseconds.
  - `ListedTable.updatedAt` and `ListedView.updatedAt` were epoch milliseconds.
  - `Producer.runAt`, `Quality.checkedAt` and `Listing.expiresAt` were passed on as written. A value
    that is not a time is now `null`.
- `DELETE /automation-principals/{automationPrincipal}` answers
  `{"deleted": true, "automationPrincipal": "<id>"}`. It was `{"revoked": true}`.
- Path parameters are named after their resource: `{teamId}` is `{team}`, `{id}` is
  `{automationPrincipal}` and `{shareId}` is `{listing}`. The URLs are the same.
- Every operation has a stable camelCase `operationId`: `getDiscovery`, `getMe`,
  `listTeamAutomationPrincipals`, `createAutomationPrincipal`, `deleteAutomationPrincipal`,
  `listAutomationPrincipals`, `getAutomationPrincipal`, `createCatalogToken`, `listTeamExtensions`,
  `listListings` and `getListing`. They were generated by FastAPI.
- Renamed fields: `TokenResponse.principal` is `automationPrincipal`, and `ListingSummary.databaseId`
  is `database`.
- Something absent is `null`, not an empty string: `Extension.purpose`, `SharedDatabase.ownerTeamName`,
  `AutomationPrincipal.createdBy`, `Listing.description`, `Listing.contact`, `ListingOwner.teamName`,
  `Column.doc`, `ListedTable.comment`, `ListedView.comment` and `PartitionField.sourceColumn`.
- Response fields that are always present are `required` in the contract, with `null` where a value
  can be absent. `Quality.status` is an enum: `pass`, `warn` or `fail`.
- Error codes, one status each:
  - A resource that does not exist has a code of its own: `unknown_automation_principal` and
    `unknown_listing`, both 404. `not_found` now means only a path that does not exist.
  - `provider_error` (502) is `platform_error`, the code the extensions use for the same case.
  - `invalid_request` is always 422. A refusal Polaris answered with 400 was 400.
- `contracts/bridge/v1/openapi.yaml` is YAML. It was JSON.
- The Apps menu script (`v1/apps-menu/apps-menu.js`) removes the listeners of a previous
  `IcebergApps.mount()` on the same element. Mounting again used to add another set.

Also new in 1.0.0:

- Capability `app-directory`: discovery gives each extension a `title` and `purpose`, and lists the
  user portal's pages in `userPortalPages` (`id`, `title`, `url`). With them every extension shows
  the same Apps menu as the user portal; the menu's script and stylesheet are in
  `v1/apps-menu/`, to copy unchanged.
- Errors: `Error.code` is an enum of every code, and the [README](README.md#errors) lists each one
  with its status and meaning. Every response that is not a success now
  has the error shape:
  - A path that does not exist answers 404 `not_found`. It was FastAPI's `{"detail": "Not Found"}`.
  - A method a path does not have answers 405 with the new code `method_not_allowed` and an `Allow`
    header. It was `{"detail": "Method Not Allowed"}`.
  - A failure the Bridge did not expect answers 500 with the new code `internal_error`. It was a
    plain-text response. A status that has no code of its own gets `internal_error` too; that
    was `error`.
- Every operation documents 405 and 500 with the `Error` schema, and discovery documents 500.
- `POST /teams/{team}/automation-principals` answers with exactly the `AutomationPrincipal` schema,
  for 201 as for 200.

## 0.1.3 - 2026-11-09

Released with core 0.9.11. Additive: extensions built for 0.1.0 to 0.1.2 keep working.

- Capability `team-extensions`: `GET /teams/{teamId}/extensions?environment=` lists the extensions
  a team enabled (active automation principals), per environment. Only for the service account of
  an extension that the team enabled itself; otherwise 403 `extension_not_enabled`. Every read is
  in the audit trail as `iceberg.bridge.team_extensions.read`. With it, one extension can serve
  another for a team only where a team administrator enabled both.

## 0.1.2 - 2026-10-17

Released with core 0.9.9. Additive: extensions built for 0.1.0 and 0.1.1 keep working.

- Discovery: `network` has `platform`, `docker` or `kubernetes`, and `namespace`, the Kubernetes
  namespace of the platform. On Kubernetes the aliases are Services in that namespace and `name`
  is the namespace (contracts/bridge/v1/network.md).
- On Kubernetes, an extension's namespace for isolated jobs carries `io.iceberg-platform.isolated: "true"`.

## 0.1.1 - 2026-10-14

Released with core 0.9.1. Additive: extensions built for 0.1.0 keep working.

- Capability `listings`: data shares that their owning team lists in a data catalog. A
  registered listing extension (`PLATFORM_LISTING_EXTENSIONS`) polls `GET /listings`, then
  reads `GET /listings/{shareId}` for the names, column schemas, descriptions, partition
  fields, producer conventions and semantic models of the listed objects. The response has
  an `ETag` and answers `If-None-Match` with 304. A listing carries no data, view SQL,
  storage location, snapshots or credential. Semantic model fields carry their `label`, and
  datasets, fields and metrics their `aiContext` rows (a field's or metric's synonyms stay in
  `synonyms`).
- Discovery: each entry of `extensions` has `listing`, true for a listing extension.

## 0.1.0 - 2026-10-04

First version, released with core 0.7.0.

- Discovery (`GET /bridge/v1`): contract version, capabilities, OIDC, catalog and storage
  endpoints, environments, network aliases and registered extensions.
- Capability `user-context`: `GET /me` returns the signed-in user's teams, roles and databases,
  re-checked on every call. Each entry of `sharedDatabases` has `recipientTeams` (the user's teams
  that received it, in membership order), `sharedObjects` (the tables, views and semantic models the
  user can read), `sharedWithTeam` (the first recipient team) and `ownerTeamName`.
- Capabilities `automation-principals` and `automation-tokens`: automation principals per team,
  environment and extension, enabled by team administrators, and one-hour `read` or `write`
  catalog tokens.
- Capability `shared-data`: a team share received by a team reaches the read role of that team's
  automation principals in the environment of the shared database, never the write role.
  `GET /automation-principals/{id}` lists these databases under `sharedDatabases`, each with the
  objects it can read, and a `read` token can load them by name.
- Table-property conventions v1 for producers, lineage and quality.
- Network aliases and role labels, and the extension handshake file.
